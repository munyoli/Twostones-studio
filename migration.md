# MySQL to Supabase Migration Skill
**Goal**: To systematically migrate a MySQL database schema and its data to PostgreSQL while ensuring compatibility with Supabase's standards [7].

## Instructions
Follow this **Chain-of-Thought** approach to ensure a seamless migration [8]:

1.  **Analyze MySQL DDL**: Extract the source schema and identify MySQL-specific data types (e.g., `TINYINT(1)`, `DATETIME`) and features like `AUTO_INCREMENT` [7].
2.  **Map to PostgreSQL/Supabase**: 
    - Map MySQL types to PostgreSQL best practices (e.g., `VARCHAR` to `TEXT`, `DATETIME` to `TIMESTAMPTZ`) [7, 9].
    - Leverage PostgreSQL-specific features like `JSONB` for unstructured data where appropriate [7].
    - Ensure every table includes a Primary Key named `id` to comply with standard safety and naming policies [10, 11].
3.  **Generate Migration Scripts**: Create a Python script (referencing `scripts/migrate_data.py`) to handle data transformation and insertion [7].
4.  **Validation**: Run a validation check to ensure no `DROP TABLE` statements exist in the final script and that all table names use `snake_case` [10, 11].

## Constraints
- **Data Integrity**: Use `BigDecimal` logic for financial calculations to avoid the precision issues found in legacy `double` types [9].
- **Safety**: Do not execute any destructive commands on the target Supabase instance without explicit confirmation [4, 10].
- **Supabase Specifics**: Ensure the schema is compatible with Supabase’s Realtime and Auth requirements if requested [12].

## Examples
- **Input**: `CREATE TABLE users (id INT AUTO_INCREMENT PRIMARY KEY, active TINYINT(1));`
- **Output**: `CREATE TABLE users (id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, active BOOLEAN);` [7, 13].
